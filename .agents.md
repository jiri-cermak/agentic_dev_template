Before delegating:

```bash
cd {PROJECT_ROOT}

git status --short
```

Confirm that the repository exists, the adapter's required environment is available, internal state is excluded, and the target files are present or intentionally created by the relay. If a required environment is missing, stop and report it; do not install packages unless the adapter explicitly permits it.

**Skill isolation:** Keep the project adapter as a dotfile. The harness scans a fixed set of project-convention files (concrete filenames defined in the adapter) for auto-discovery. A dotfile is invisible to progressive subdirectory discovery, preventing the harness from injecting it as a virtual skill. The relay context is the subagent's sole source of rules.

## Local testing adapter

Every relay must declare exact commands appropriate to its artifact. Include:

1. one structural runtime assertion;
2. one negative assertion;
3. runtime proof when the artifact is served or executable;
4. browser/DOM proof when UI or client-side behavior changes.

The adapter may define Python stdlib replacements, browser commands, server startup, ports, cleanup, and provider-specific fallbacks. Do not put those assumptions into the core unless they are genuinely project-agnostic.

## Local test output hygiene (mandatory)

The canonical test command emits an artifact, a hash, and the filtered signal. Third-party INFO chatter is not evidence; the hash is. Pattern:

```bash
cd {PROJECT_ROOT}
mkdir -p handovers/{TASK_ID} \
  && {TEST_COMMAND} 2>&1 \
  | tee handovers/{TASK_ID}/test_output.full.txt \
  | grep -vE '{THIRD_PARTY_NOISE_FILTER}'
sha256sum handovers/{TASK_ID}/test_output.full.txt
```

- The artifact file (`handovers/{TASK_ID}/test_output.full.txt`) is the unabridged record; the handover references it.
- `## Raw Test Output` carries the **filtered signal verbatim, plus the artifact path and its `sha256`**. "Raw" means raw signal, artifact-hashed — never the raw stream.
- A failure must never be summarized.
- Prefer the lowest verbosity level that still keeps full failure/error blocks and the final summary line, and confirm your test runner records failures unconditionally (verbosity gates only the per-test "ok" lines).

## Local execution profile by tier (mandatory)

A relay declares its tier's reasoning effort, and the Architect makes that declaration real by writing it to the harness's profile/reasoning config **before dispatch**. Declaration alone does nothing — relay context is text, and the delegation mechanism does not carry a reasoning parameter. Only a config change on the spawn path alters a subagent's reasoning level.

**Tier → effort:**

| Tier | Reasoning effort |
|---|---|
| minimal | off (`false` / `none` / `disabled`) |
| standard | `medium` |
| full | `high` |

**Before every dispatch**, write the tier's value against the profile's home using the config command the harness provides (prefer absolute paths; `{SUBAGENT_REASONING_CONFIG_COMMAND}`).

Caveats:
- Concurrent spawns share one value. For parallel relays needing different effort, split them across profiles rather than interleaving writes.
- Spell "thinking off" as `false` / `none` / `disabled`. `null`, or omitting the key, does NOT disable it — parsers typically fall back to a default (often `medium`), so a minimal relay silently runs hot. The key to set is `{SUBAGENT_REASONING_EFFORT_KEY}`.
- Reasoning tokens bill as output tokens — effort is a cost lever, but clarity, not model effort, drives iteration count. Do not raise it to compensate for a loose relay.

## Local delegation timing & tier recording (mandatory)

Record every subagent spawn in `devlog.md` with two mandatory fields — no unlabeled spawns and no self-reported timing:

1. **Tier** — classified at dispatch time per `CORE_PROTOCOL.md` requirement clarity (loose → minimal, medium → standard, tight + ≥3 relays → full, tight + <3 relays → standard). Format in the delegation bullet: `(tier: minimal | standard | full)`.

2. **Fs-derived duration** — measured from filesystem timestamps, never the subagent's self-reported runtime:
   - START = mtime of `handovers/<TASK-ID>/relay.md` (write/touch the relay into the task's handover dir at dispatch; its mtime IS the dispatch stamp).
   - END = mtime of `handovers/<TASK-ID>/completion.md` (final handover file).
   - DURATION = END − START, in seconds.
   - Record in the devlog bullet as: `⏱ <Ns>s [relay.md <START-ISO> → completion.md <END-ISO>]` — both timestamps ISO-8601 UTC.
   - Every stated duration must be reproducible from the two named files' mtimes (`stat -c '%y' <file>`). Subagent self-reported runtimes are never the timing source.
